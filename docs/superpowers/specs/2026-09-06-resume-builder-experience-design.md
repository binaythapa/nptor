# Resume Builder Experience Design

## Goal
Evolve NPTOR's existing CV workspace into an original, Resume-Now-inspired resume-building experience: fast section editing, live preview, autosave, job targeting, ATS feedback, and human-approved AI writing, while preserving the existing Career Profile as the reusable source of truth.

## Product principles
- Reproduce useful product behavior, not proprietary UI, branding, copy, or implementation.
- Keep Career Profile as the master data source; each CV remains an independent presentation/targeting layer.
- AI suggestions are never silently persisted. The user must explicitly apply them.
- Preserve existing CV routes and exports so current users are not broken.
- Use the existing Django server-rendered stack and vanilla JavaScript rather than introducing a SPA framework.

## Experience
### Builder workspace
- Desktop: three functional areas: section navigation/editor, content workspace, and sticky live preview.
- Mobile: collapse to section navigation + editor; preview opens as a dedicated panel/modal.
- Sections: Contact, Summary, Experience, Education, Skills, Projects, Certifications, Achievements.
- Existing drag/drop selection ordering remains supported.
- Autosave changes after a short debounce and on navigation/visibility changes.
- Save state is visible as Saved/Saving/Unsaved/Error.

### Job targeting
Each CV stores a `target_job` object inside its existing `overrides` JSON field:
- `title`
- `company`
- `description`

This avoids a migration while keeping targeting isolated per CV. The target is reused by ATS analysis and tailoring.

### AI writing
The builder exposes explicit AI actions:
- Improve summary
- Rewrite an experience bullet/description
- Suggest skills for the target role

AI output is returned to the browser as a suggestion. The user can apply or dismiss it; applying only changes the editor state, and autosave persists it afterward.

All prompts use the existing truthfulness rule: AI must only use supplied facts and must not invent dates, employers, metrics, certifications, achievements, or responsibilities.

### ATS/job matching
- Target job description is editable in the builder.
- A Check ATS action calls the existing ATS service and returns the score, keyword match, missing keywords, gaps, and recommendations.
- Existing full ATS analysis page remains available for detailed results.

### Existing capabilities preserved
- Career Interview and extraction confirmation.
- Resume import/review.
- AI review.
- Tailoring for a job.
- Version snapshots.
- PDF/DOCX export.
- Template selection.

## Technical design
### Backend
- Add JSON endpoints under the existing `cv` URL namespace:
  - `POST /cv/<id>/builder/autosave/`
  - `POST /cv/<id>/builder/ai/`
  - `POST /cv/<id>/builder/ats/`
- Reuse `CVBuilderForm` validation for normal form saves.
- Reuse `build_cv_payload()` for preview/export consistency.
- Extend `cv.services.ai.cv_writer` with structured skill suggestions while retaining provider abstraction.
- Keep all CV mutations scoped to the authenticated owner.

### Frontend
- Replace the current builder presentation with a responsive workspace.
- Use semantic buttons and accessible labels.
- Use `fetch()` with the existing CSRF cookie for JSON endpoints.
- Debounce autosave to avoid excessive writes.
- Reload the existing preview iframe after successful saves so the preview is generated by the canonical renderer instead of duplicating rendering logic in JavaScript.

### Testing
- Add Django tests for autosave validation/ownership and AI endpoint behavior.
- Add service-level tests for skill suggestions and truthfulness metadata.
- Existing AI provider regression tests remain unchanged and must continue to pass.

## Non-goals for this implementation
- Copying Resume Now's visual design or source code.
- Introducing React/Vue or a new frontend build pipeline.
- Implementing subscription/billing changes.
- Building a new cover-letter domain model; existing CV capabilities remain the integration point for future cover-letter work.
